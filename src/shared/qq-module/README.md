# QQ 模块契约

本目录定义宿主与 QFCA 之间的 JSON 契约、运行时校验和接口版本协商。已有 QQ 设置和内建 NapCat 继续供应生产渠道。当前桌面入口提供安装条件预检。

- `QQ_API_SUPPORT` 声明源码实际支持的版本。新增字段时应同时提供对应 minor 的校验与能力协商。安装包版本、发布来源和平台支持由宿主包校验另行确认。
- `runtime.ts` 定义握手、初始化、生命周期、消息确认以及专属 IPC 的请求和事件。宿主与模块分别核对 `connectionEpoch` 和账号。账号及权限以宿主验证的连接状态为准。
- 入站必须明确区分私聊与群聊。群聊的提及和一层引用由宿主转换。文本长度以 UTF-16 单元计，帧大小以 UTF-8 字节计。
- `validateSendResult` 用原请求核对操作 ID、分片数和返回顺序。部分或未知结果由上层保守记录，以避免重复投递。
- `media.ts` 提供四个受限的分块操作。媒体句柄限定字符集和长度。宿主按当前授权使用媒体 broker，校验长度、偏移和摘要，并负责缓存回收。每块最多 64 KiB，每文件最多 100 MiB。

跨仓兼容性、进程验证和生产启用条件见[QQ 可选模块同步与验证](../../../docs/design/2026-11-26-QQ可选模块同步与验证.md)。
