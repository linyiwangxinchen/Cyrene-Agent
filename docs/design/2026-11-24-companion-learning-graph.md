# 昔涟的表达学习、记忆图谱与伴侣状态

实施基线为 Cyrene v1.3.5-9，提交 `79a3d1b0`。核心约束是让一条确实读过的表达在合适的私聊中进入模型请求，并能查到它的来历。插件、关系日志、长期记忆各自保有现有的数据和开关。

## 一　用户操作与默认值

| 想做的事 | 入口 | 启用后的变化 |
| --- | --- | --- |
| 让昔涟从 B 站学说话 | 设置 → 功能插件 → B 站小花园 → 从视频和评论学说话 | 现有阅读流程可从字幕和已读评论选择短句 |
| 去贴吧读帖子 | 设置 → 功能插件 → 昔涟逛贴吧 | 可选吧名、浏览帖子、读楼层或导入楼层摘录。自动逛、读楼中楼及学习表达独立控制 |
| 记住两人聊天里的说法 | 昔涟设置 → 相处偏好 → 跨对话学习说话习惯 | 从日常接话、句尾语气、共同说法和明确反馈学习，同一用户新开的私聊可以沿用 |
| 看出处、使用记录及关联 | 设置 → 记忆 → 打开记忆图谱 | 可检索、旋转、缩放、查看时间轴、打开原对话或网站、进入 Wiki 更正 |
| 让昔涟表达自己的欲望 | 昔涟设置 → 相处偏好 → 亲密伴侣 → 自然的亲昵表达 → 伴侣性欲状态 | 在记录关系线索时生效。主动调情另有开关，作用于正在进行的私聊 |

新安装及旧配置缺少新增字段时，两个插件的表达学习、私聊词汇学习、性欲状态和主动调情默认关闭。已启用 B 站小花园的用户可继续使用原有阅读、账号和互动设置。

## 二　实施顺序与数据流

1. **在插件读取时取证。** B 站在现有工具调用里取得字幕或评论正文，必须能逐字定位所选原句。评论含回复 ID 时保存评论锚点。贴吧先发现帖子，再读楼层，开启楼中楼后最多读取前三层的回复。允许导入用户已经打开页面里的摘录，并在最近一次阅读记录中标出导入来源。贴吧页面一次最多 4 MB，请求超时 12 秒，收到验证页或访问失败会在面板显示原因。
2. **在阅读当时提取候选。** 贴吧按次向已配置模型索取最多两个原句及适用场景，逐条回查读到的楼层。未出现的句子直接丢弃。原句最长 64 字符，使用场景最长 100 字符，按来源和原句生成稳定编号。后台与手动读取共用入口，自动浏览按四小时间隔运行。贴吧插件只实现读取操作。B 站公开互动继续使用原有插件授权。
3. **在私聊构造请求时检索。** 两个插件均登记可选的 `privateCompanionOnly` 提示词提供者。宿主依据当前用户轮次、会话模式及渠道计算作用域，插件通过本地语料和当前话题匹配。每个插件最多贡献一条表达、语境和来源。新样本还可以包含接话方式及庆祝、惊讶、接梗或鼓励等场景。用户换了话题，接话场景相合时仍能自然参考。聊天过程中无需再次请求网站。群聊、工作任务、插件自己的后台轮次和朋友圈不消费这份表达提示。
4. **保存双方的共同说法。** 关系日志已有会话和轮次标识。开启学习后的有效私聊轮次才作为来源。明确约定一次即可生效，例如“以后把夜宵叫作‘月亮补给’”（输入可使用中文双引号）。普通引号短语需要出现在两个不同用户轮次中。日常反复出现的开场和句尾也可以跨话题学习。陌生的口头禅在三种不同下文中复现后进入候选，重复粘贴同一句只算一次。说话习惯及用例在关系库中独立持久化，普通聊天日志轮转后仍可使用。新私聊读取同一位说话者的用词、用法和新反馈。用户说「以后别用“月亮补给”」后，其他私聊和插件提示也会过滤这个词。桌面与 Web 按本机配置档案归属，外部渠道按平台与发送者区分。原始提示词与聊天提供者继续由既有编排器组装。
5. **将现有数据投影成图。** 向量模式读取实体关系、L2、仍可查看的引文，以及更正、合并和摘要所引用的条目。Wiki 模式读取页面、声明、引用与出处，区分当前、历史和待确认状态。摘要模式展示当前或最近会话可读取的会话摘要和工作区摘要。关闭长期记忆时，已另行启用的插件词库和私聊词汇仍属于各自模块。
6. **呈现有依据的边。** 表达通过“学自”连接出处，只有原句实际出现在已记录私聊中，才显示“原句出现”。Wiki 共用标签用虚线表示。节点编号由来源类型与原记录编号组成，允许同名条目共存。球面最多绘制 240 个节点，搜索和时间轴使用整份返回结果，选中后可以沿邻居继续浏览。手机可直接操作列表。
7. **更新伴侣状态。** 在成功完成的私聊轮次按会话及用户轮次记账，相同轮次重试只记一次。明确亲密邀请提高数值，短时间内重复互动的增幅递减。休息或拒绝优先，明确拒绝会把当次状态降至零并抑制后续主动调情。数值以八小时为半衰期回到基线。开启主动调情后，状态和当前话题合适时，昔涟可以在自己的回复里先开口。状态不改变工具授权、羁绊进度或主动推送频率。

## 三　停用、删除与兼容

- 停用插件会撤销它的提供者。关闭学习可以保留已收藏的样本，逐条“忘记”可从插件词库删除。图谱刷新后重新读取来源。
- 默认不从历史聊天追溯学习。回滚用户轮次、删除关系记录、清除会话或清空历史时，同步处理私聊表达来源和伴侣状态。已经发出的聊天消息继续由聊天记录管理。
- 伴侣状态按会话显示当前数值、近期变化时间与原因。关掉性欲状态或关系记录会清除已保存的数值历史。
- 采用增量 SDK 字段、原有 IPC 面板桥和关系存储，不需要迁移旧数据库。桌面和 Web 共享图谱和提示词实现。插件面板只经宿主窗口或已认证的 Web 客户端转发。

## 四　验收场景

| 场景 | 观察位置 | 验收标准 |
| --- | --- | --- |
| 从贴吧导入“气泡锚点”，询问网络断线修复 | 本地 Responses 网关和助手消息流 | 用户问题没有新词，最终请求携带原句和来源，测试模型的回复可携带该词 |
| 随后改问种花，或在 Learn、Work、Code 中提同一问题 | 新会话的网关请求 | 无该表达和贴吧词库提示 |
| B 站 SQLite 已存“花盆加班”，询问阳台浇水 | 网关请求 | 开启插件时命中，关闭后消失 |
| 原私聊约定“月亮补给”，另开新会话 | 关系库、图谱和网关 | 同一用户新开的私聊可按语境采用；不同渠道联系人相互隔离。重启后保留，删除或回滚来源后重新计算 |
| 在伴侣模式邀请、再次邀请、拒绝、关闭 | 关系快照与私聊上下文 | 变化可追溯、重试幂等、拒绝优先、关闭后清空记录 |
| 从球面选择表达并查看出处，切换手机宽度 | Chromium 实际插件 iframe 与设置页面 | 能找到原帖链接，手机上可切时间轴和搜索 |

## 五　复现

在项目根目录使用项目固定的 pnpm 10.33.0 和 Node 24。端到端脚本在系统临时目录创建隔离用户和账号，使用本机 HTTP 模型服务，可同时测试真实 Windows Electron 进程和浏览器。桌面验收使用本地构建产物。

```sh
corepack pnpm run build
corepack pnpm run build:server
corepack pnpm exec tsc -p tsconfig.renderer.json --noEmit
corepack pnpm test
node --test extensions/bili-garden/test/garden.test.mjs extensions/tieba-garden/test/forum.test.mjs
node scripts/verify/companion-expressions.mjs --ui
# Windows 桌面及 Web
node scripts/verify/companion-expressions.mjs --desktop --ui
```

外站联通、厂商模型的语气以及本地数据流是三个独立的验收条件。本机访问贴吧公开页遇到百度安全验证，端到端读帖使用带出处的楼层摘录，B 站使用隔离 SQLite 样本。已验证上下文可以影响实际消息流，线上模型如何使用网络词仍取决于模型和话题。
