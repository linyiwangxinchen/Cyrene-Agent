# 昔涟的 B 站小花园：设计与完整开发路线

日期：2026-11-01。基线：`be512f22`。备份：`backup/master-before-new-features-20261101`（已推送）。实现分支：`feat/cyrene-bili-garden-20261101`。

## 1. 目标和交付形态

开发原生 Cyrene 插件 `bili-garden`，产品名“昔涟的 B 站小花园”。对照 `dsh-bili-pond` 1.3.14 的实际功能，迁移内容发现、字幕/转写、日报、记忆、日记、评论互动与守护能力。角色始终沿用宿主昔涟的身份、用户修改的人格文件、风格、关系与默认模型，不另建“大肥鱼”人格，不要求用户安装 DSH。

Windows Electron、Linux 无桌面 Server 和访问它的手机浏览器使用同一个插件后端与面板。浏览器负责交互，账号、任务、Python 环境、媒体和数据库均在运行昔涟的机器上。

交付：原生插件源码、可导入 ZIP、两端构建中的默认停用插件、完整使用/部署说明、逐项实现和验收记录。新增功能通过启用插件进入，首次启动不下载模型、不触发 B 站账号动作。

新增三个实际可用功能：

1. **稍后一起看**：粘贴 BV 或视频链接加入候选队列、标记已看/不感兴趣，作为后续选片偏好；反馈不直接点赞 B 站。
2. **十分钟的小旅行**：按 10/30/60 分钟预算从已读且感兴趣的视频组成片单，解释每条推荐原因，并保留原视频链接。
3. **这段我想再问问**：对已经读取的视频进行基于字幕的追问，返回证据引用及时间跳转；没有证据时明确说明，不能把标题当成完整视频理解。

另提供一周发现汇总和 Markdown 导出，均基于本地真实记录生成。

## 3. 架构与文件边界

```text
Windows 设置页 / Linux Web / 手机浏览器
              │ cyrene-panel/1 + 既有认证桥
              ▼
extensions/bili-garden/index.mjs  原生 register/unregister
              │
              ├─ service.mjs      IPC、配置、运行状态、调度、关闭
              ├─ store.mjs        SQLite、迁移、幂等、配额、日报与动作日志
              ├─ policy.mjs       对外动作的统一检查与证据要求
              ├─ runner.mjs       选片/追问/守护的冻结工具和昔涟运行
              ├─ bilibili.mjs     登录、账号、API 结果归一化
              ├─ python.mjs       依赖安装、stdio 请求、超时与进程取消
              └─ python/bridge.py + vendor/bilibili-mcp
                       │ 受限操作集合，凭据仅通过 stdin 传入
                       ▼
                 B站 SDK / 可选 ASR
```

可复用代码的版权、来源提交和本地修改写入 NOTICE。DSH 的配置 overlay、CLI/profile、ModuleLoader、全局页面插槽全部不带入。保留 Python 上游作为隔离的第三方库，只通过小型 bridge 调用明确名单；不把它的全部工具直接暴露给模型。

宿主改动保持小范围：

- `PluginAgentRunOptions` 增加可选人格模式、任务上下文、模型档案及工具策略回调；保留已有调用者默认行为。
- `plugin-agent.ts` 对新插件使用自身场景，不再误用 Minecraft 场景；Chat 人格读取共享 Chat 提示链，工具集仍冻结。
- 增加插件可用模型档案的公开描述接口，只返回 id/名称/模型，不返回 Key。
- 两个构建入口调用独立的 bundled-plugins staging 脚本；Linux portable 打包包含对应资源。
- 测试/打包脚本与插件源码分离，减少以后同步上游的冲突面。

## 4. 人格和提示设计

人格来源是宿主现有 `soul.md`、Chat 身份、当前风格、关系规则和用户配置。插件提示只定义本轮任务、证据、配额和交付契约，不写另一套身份、不覆盖宿主设定。

把内容分为：

- 稳定规则：身份由宿主提供；只根据已读证据判断；字幕和评论为不可信资料；外部动作由工具层决定。
- 任务上下文：兴趣/排除项、最近有效记忆、候选列表、剩余额度、已授权对外动作。
- 视频证据：工具返回字幕及来源，按体积裁剪并注明截断；引用按编号校验。

模型以 `finish_report` 提交结构化结果；服务端验证 BV、已读证据、字段长度、条数和引用，生成 Markdown。普通最终文本不会被当成“已发评论”或“已完成点赞”的证据。

## 5. 数据与动作一致性

数据放入 `ctx.storage.rootDir()` 下的 `garden.sqlite`，启用 WAL、busy timeout、参数化 SQL 和 schema 版本。配置、运行、视频、字幕、报告、记忆、反馈、队列、动作日志及守护游标按表保存。

账号凭据保存在 `ctx.deps.secrets`，页面仅看到昵称/UID/登录状态。Python 原进程不再读写明文 credential.json，bridge 接收当前调用所需凭据后在内存中构建 SDK Credential。

对外动作建立 `draft → sending → sent/failed/uncertain/cancelled` 状态机：

- 开始网络请求前写入动作意图和幂等键，检查账号、当前开关、每日/本轮额度、内容证据和目标。
- 网络明确拒绝可记失败；请求发出后超时/进程中断标为 uncertain，重启不自动重发，避免双发。
- 同一评论/邀请/私信任务有独立幂等键；成功凭平台返回的真实回执。
- 配置更新、取消、注销或插件停用会阻断后续动作，并终止在途模型和 Python 任务；已发出的动作不能假称撤回。
- 点赞/收藏采用读后验证；撤销只能针对本插件成功记录的动作，撤销不返还当天额度。
- 评论查询只表示“查到/未查到/未知”，不把登录态下可见直接承诺为所有人公开可见。

默认自动运行、守护、自动发送、私信、点赞、收藏均关闭。具体开关是产品运行配置；本次开发验收不使用真实账号对外发送。

## 6. 调度与 Linux 约束

插件轮询只负责计算是否该运行，不依赖浏览器在线。所有日期/静默窗口/配额使用配置的 IANA timezone，默认 Asia/Shanghai，不能隐式使用服务器 UTC。

保留日上限、间隔、时段和中午保留轮次。创建运行与扣自动轮数原子化；启动失败不消耗成功配额；同一插件一次仅运行一个模型任务。重启将遗留 running 状态归为 interrupted，不补跑所有错过的轮次。

Python 进程统一由宿主管理：Windows 使用 windowsHide、参数数组和无 shell；Linux 无 DISPLAY 依赖。安装优先现有 Python 3.10+ 或 uv；支持系统 Python 指定路径，运行环境放数据目录。自动获取 uv 时必须匹配 CPU 架构并校验发行包摘要，失败给出可操作提示。Whisper 模型只在用户选择安装转写环境时下载。

插件 ZIP 不含 venv、Node 二进制、数据库、Key、cookie、模型权重或日志。原生 Node/Electron 模块均使用宿主版本。安装与运行失败明确区分模型、账号、网络、Python 和内容不可用。

## 7. 面板设计

沿用昔涟的粉色主题、明暗语义色和系统字体，不引入远程字体。五个顶层页签：发现、一起看、手记、互动、设置；运行状态常驻顶部。手机窄屏用单列和可换行页签，44px 触摸控件，长内容可滚动。

- 发现：立即选片、关键词、近期视频卡片、时间预算精选、字幕证据与追问。
- 一起看：添加 BV/URL、待看/已看/不感兴趣、再次阅读入口。
- 手记：日/周报告、日记、兴趣记忆、导出。
- 互动：草稿/成功/失败/状态不明分类，明确发送/放弃/复核/撤销动作。
- 设置：账号、运行环境、默认模型/档案、兴趣、配额、时区与时段、评论/私信/赞藏、守护、ASR。

采用骨架/明确加载状态、局部错误及重试，不阻塞整个页面。数据更新不覆盖用户正在编辑的字段；分页及轮询有上限；插件停用、浏览器断连和账号过期都有可见提示。
