## 已接入

| 区域 | 宿主策略 |
| --- | --- |
| 模块和包 | 专属进程通过私有 IPC 协商接口、身份和能力。包存储校验签名、摘要、归属、版本和单调发行序号，落盘与选择指针分开提交。 |
| 桌面设置 | 在现有 QQ 设置中查询可选模块条件。预检仅请求监听参数，宿主读取已保存的 QQ 凭据后返回状态枚举。保存密钥和实际监听操作仍走原设置。Web 使用现有 QQ 设置。 |
| 迁移 | 旧 NapCat 停收并排空后观察真实监听关闭。独立进程在隔离期协商，迁移写入选择记录后再开放收发，接口返回成功前还须取得同账号和同代次的激活证据。 |
| 渠道隔离 | 普通插件注册端口保留宿主 QQ 身份。在途事件由活跃连接校验，宿主用经过协议握手核对的账号构建私聊作用域。 |
| 消息与媒体 | 模块通过不透明句柄和有界分块传输，宿主确认落盘后才确认接收。迟到发送受代次、当前授权和取消检查限制，部分送达映射到结果待确认。 |

## 可复现验收

在单独目录检出上面固定的 QFCA 提交，执行 `npm ci --ignore-scripts`、`npm run check`、`npm test`、`npm exec -- tsc -p tsconfig.build.json` 和 `npm run smoke`。完成后在 Cyrene-Agent 根目录运行以下命令。

```powershell
corepack pnpm exec vitest run src/main/qq-modules src/shared/qq-module src/main/channels/adapters/qq src/main/channels/manager.test.ts src/main/channels/qq-listen-policy.test.ts src/main/channels/settings-store-qq-preflight.test.ts src/renderer/react/features/settings/QqModuleInstallationCard.test.tsx
corepack pnpm run build:main
$env:QFCA_ROOT = 'C:/path/to/reviewed-QFCA'
$env:QFCA_ENTRY = Join-Path $env:QFCA_ROOT 'dist/runtime/entry.js'
$env:QFCA_LARGE_MEDIA_TEST = '1'
corepack pnpm exec vitest run src/main/qq-modules/qfca-compatibility.test.ts src/main/qq-modules/qfca-media-compatibility.test.ts
./node_modules/.bin/electron.CMD scripts/verify/qq-module/electron-transport.cjs
```

跨仓用例在临时目录使用回环后端和合成文本、图片、音频、文件及视频。Electron 夹具调用实际的宿主进程接口。现有 QQ 数据、默认用户配置和真实账号继续由原渠道管理。

Windows 联合定向回归跑通 95 个文件、1,086 项测试，5 项平台条件用例跳过。已显式启用固定 QFCA 入口和 100 MiB 媒体用例，核对 1,600 个传输分块与 SHA-256。独立 QFCA 候选另通过 304 项及编译后的 IPC 冒烟。

编译后的本轮桌面代码还通过了 Windows Electron 验收。实际 `utilityProcess.fork` 启动固定 QFCA 候选，验证错误令牌返回 401、正确令牌恢复预期 QQ 账号、已授权私聊进入宿主、回复在收据回调返回后仍按原账号投递一次，以及停止后清除内存中的账号作用域。

旧 NapCat 使用真实反向 WebSocket 和持久队列验证延迟回复。入站收据落盘即完成，模型回信继续使用接收消息时认证的连接。迁移停收会等待已接收的回信，普通重启会阻止旧回信写入新连接，即使新连接登录同一个账号。编译后的 Web 共享核心通过全部 34 项端到端验收，其中 QQ 用应用设置启用旧渠道，鉴权后发入私聊，调用回环测试模型，收到实际 OneBot 回复并核对渠道日志与会话绑定。
