# 昔涟记忆与表达学习实施规划

基线为 `1.3.5-14` 的 `e37fc4df`。本文定义交付范围、优先级和验收，运行契约及迁移步骤见[技术方案](./2026-11-26-昔涟记忆与表达学习技术方案.md)。

## 一、交付目标

- 主人能在新私聊准确回忆有来源的事实，可以更正、忘记或关闭自动使用。已经删除的来源在重启和重放后仍保持失效。
- 昔涟能学会明确的相处偏好、共同说法和经过多次观察的说话习惯。临时要求、否定、转述和任务素材保留原有语义。
- B 站、贴吧和授权插件通过同一个宿主契约提供表达证据。每份证据有出处、使用条件和可操作的撤回入口。聊天请求从本地样本取用，外部阅读沿用各插件原来的任务入口。
- 台词和人格提示继续提供角色语气。表达学习由情境和用户反馈调节，用于选择怎么接话。输出质量以可回放的请求、实际生成的回复和人工盲评分别验收。

## 二、设置与兼容矩阵

| 场景 | 实施后的契约 | 验证方法 |
| --- | --- | --- |
| 向量、摘要、Wiki | 各模式维护原本的存储和入口。向量模式的普通文本 Chat 增加有范围的 L2 默认召回 | 对同一事实分别走三个模式，并核对具体存储、模型输入与来源展示 |
| 长期记忆关闭 | 停止个人事实和近况的自动提取、模型侧召回及在途提交。既存条目仍可在设置页查看及删除 | 请求捕获、存储核对及重启三方比对 |
| 本地桌面与 Web Chat | 复用本地档案及获准的私聊历史，统一回执和来源操作 | 真实 AG-UI 入口与认证 Web 入口 |
| 外部私聊、多联系人绑定相同会话 | 个人资料按平台、机器人账号和联系人过滤。历史绑定与个人身份各自校验 | 分别通过两个渠道联系人送入样本，核对正向与反向召回 |
| 群聊、插件后台、Work、Code、Learn | 陪伴学习只在符合资格的私聊采集及应用。已有通用提示词及工具契约继续可用 | 普通发送、后台运行、计划模式和权限回归 |
| B 站、贴吧和其他插件 | 保留阅读、登录、扫描、回帖和启停契约。表达学习按来源授权，普通取用和主动取用各有控制 | 已有插件套件、停用、重读及撤回用例 |
| 现有用户配置 | 兼容缺少字段的旧配置。明确聊天偏好的原有默认行为继续适用。新增跨渠道共享及插件主动使用默认关闭 | 旧配置启动、逐项开关、关闭后重启 |

## 三、五阶段交付

| 阶段 | 实现顺序 | 完成条件 |
| --- | --- | --- |
| 1. 修读写边界 | 统一本轮访问范围、关闭及在途校验，然后接入普通 Chat 的 L2 召回 | 同样的输入在关闭、群聊、插件后台和其他联系人下都没有个人记忆注入。已启用的本地 Chat 能召回一条跨会话旧事实 |
| 2. 建立来源和撤回 | 复用权威消息修订与记忆治理，持久化撤回和重试，最后导入可核实的旧数据 | 更正、编辑、删除、后台任务错序、进程中断、重复迁移和兼容恢复都有可核对结果 |
| 3. 完善私聊表达 | 分清明示偏好、观察到的习惯和当前轮约束，接通持久纠正和可见操作 | 引用、否定和临时要求的回归通过。明确偏好跨会话可用。成功、失败、编辑和重启路径一致 |
| 4. 接通外部表达 | 先统一宿主策略与 B 站、贴吧来源，再发布兼容 SDK 扩展 | 原句可定位，撤回后重读不会复活，停用立即退出取用。结构化表达入口只接受枚举策略。现有插件回归全部通过 |
| 5. 评测及验收 | 在实际入口捕获请求与持久事实。固定样本对比风格和事实，再验证完整构建与交付文档 | 范围和正确性硬规则全部通过。输出盲评给出可复核的样本和评分。未覆盖的本地模型、真实渠道或平台条件单列 |

阶段 1 和 2 优先保证获取与撤回。私聊表达和插件结构化接口可以在前置契约确认后独立施工，合并时按依赖验收。ABI、IPC 和数据迁移由主工作树统一校验。

## 四、评测设计

### 必须覆盖的场景

1. 本地用户表述一个稳定事实，经过持久化、结束进程、开新会话后追问。修改事实后只用新值，删掉事实后不再返回旧值。
2. 同轮有个人原子、向量画像或派生条目时，撤回选中记忆，检查关联项、无关同轮事实及在途提取。模拟索引清理失败并重启。
3. 两个外部私聊绑定同一内部会话，绑定变更发生在主动消息的两次生成之间。捕获每次模型请求和拟投递正文。
4. 用「这次不要用」「以后不要用」「朋友说不要用」「我不喜欢」「别把失败叫作光荣」「下班以后」等样本验证采集。明确约定、持久纠正、重新允许和编辑后的消息也进入用例。
5. 模拟 B 站字幕、评论，贴吧公开实读、登录实读与手工导入，以及第三方插件。重复读、内容转载、来源失效、删除再读、插件禁用和模型忽略建议均有断言。
6. 对比闲聊、倾诉、紧急话题、正式说明、话题切换和长间隔回访。盲评维度为是否接住具体事实、是否尊重当前要求、语气自然度、重复用词和未经证实的表达。

### 测量与放行

- 自动测试从生产入口断言实际输出契约。重点断言模型请求内容、持久化状态、可见回执和重启行为。
- 回归测试使用测试数据库、模拟渠道和本地模型网关。线上模型质量比较使用合成样本和明确选定的模型。记录模型、样本、温度或可用随机设置和评判者所见内容。
- 对越权注入、撤回后复活、假成功及重复外发采用零容忍。普通文本 Chat 的默认路径沿用一次回复请求。后台抽取和索引的额外请求单独计量。记录首次响应与提示体积变化。
- 提交前运行相关 Vitest、两个插件的 Node 测试、四组 TypeScript 检查和构建。完整套件结果应报告失败、跳过、重跑和实际环境。

## 五、风险与实施边界

| 风险 | 处理方式 |
| --- | --- |
| 旧记录缺少主体或修订 | 保留旧数据并标记等待确认，验证后进入自动召回。已有可证明来源按原 ID 迁移 |
| 多存储部分写入 | 先提交读取侧撤回标记，派生清理可重做。权威旧记录保留只读备份及恢复路径 |
| 插件兼容回归 | 兼容现有提示词提供者，初版仅迁移两个内置表达入口，旧 `provide` 继续处理原有通用上下文 |
| 表达过度个性化 | 当前要求优先，按情境及次数限制引用，保留明确停用和可见来源 |
| 恢复旧版时绕开撤回 | 只回退到读取同一撤回记录的兼容版本，或先导出经撤回过滤的数据副本 |

项目实施在源码及隔离验收目录内进行。隔离验证的用户档案、模型网关和渠道回执均由测试夹具提供。真实外站或真实模型的专项结果以实际执行记录为准。

规划复核时，现有定向 Vitest 46 个文件、625 项通过，B 站与贴吧 Node 测试 86 项通过。基线复核确认了三组风险。记忆模式和主动消息的取用条件不一致，编辑修订与明确纠正的生命周期混用，旧插件提示词和新表达消费可能双重注入。

## 七、启用与回退

1. 启动时保留现有记忆模式和手动设置。长期记忆关闭后仍可从记忆面板导出、查看和管理现有数据。
2. 已启用插件须先在各自面板允许采集。然后在设置的偏好页展开「插件表达使用范围」，分别控制普通私聊与主动消息。主动取用初始关闭。B 站视频作为内容分享由既有分享开关控制。
3. 在本地示例私聊用明确句子建立共同说法，开新会话复测，再提出明确纠正。成功回复的「本轮参考了什么」只列实际传给模型的私聊偏好和共同原话，可打开来源会话。
4. 分批验收时先使用合成样本或已授权测试账号，保存开关前后的请求和回执。出现串聊或撤回后回流时关停受影响的取用入口并核对权威来源。若需要回退版本，先通过当前版本保留经过撤回过滤的数据和治理标记。
