# 昔涟对话、记忆与世界连续性实施方案

基线使用本地 1.3.7 主版本及工作树中已接通的三种记忆兼容读取、手动引用和旧会话工具。修改保留这些工作。本文承接 [记忆与表达学习技术方案](./2026-11-26-昔涟记忆与表达学习技术方案.md)，定义这次增量的实现、兼容和放行条件。

## 1. 施工范围与依赖

| 范围 | 权威入口 | 本次改变 | 兼容条件 |
| --- | --- | --- | --- |
| 私聊表达 | `buildAgentRunOptions` 与现有渠道、关系、角色档案 | 本轮场景、接话动作和最近有效轮次，优先学习外部口语策略 | 保持模型可见回复格式、人物档案、用户设置、公开聊天和任务入口 |
| 长期记忆 | 权威会话来源、后台抽取、各模式存储和召回入口 | 细节与梗概、事件日期、共享查询规划和分匹配强度注入 | 存储可读，来源核验、工作区范围、关闭及更正语义继续生效 |
| 翁法罗斯 | 现有世界引擎、日程、归档和关系回顾 | 按实际依赖提交，严格限制回顾来源，保存重大事件依据与时序 | 原有世界继续推进，旧存档和编年史继续可读 |
| 历史工具 | 权威会话轨迹和现有工具注册 | 有界全文候选、查准短词及日期、稳定翻页、来源定位 | 保留 `search_chat_history`、`read_chat_history` 的原参数和权限 |

用户消息中的“会议”按前后文理解为“回忆”。施工范围限于上述四项。新版数据由现有设置和工具调用入口接入。B 站、贴吧和其他插件保留原有阅读授权和入口，聊天时使用已有本地表达证据。本轮的构建用于验证工作树。

施工顺序为先冻结基线和共享契约，再修世界的两处缺陷，同时完成对话、记忆和历史模块。历史与记忆共同消费同一个纯查询规划器。最终在主进程和 Web 共用的实际请求入口做集成验证，再运行完整回归。模块之间只通过下列已列出的数据交接。

## 2. 私聊的说话前准备

1. 保留模式人设和工具规则所在的稳定提示前缀。可变内容写入运行时尾部。固定事实来自角色档案、当前渠道和现有可见关系。虚拟地点和活动使用世界引擎给当前会话的快照。世界材料只在与当前问题有关时用于台词。
2. 从已经过范围过滤的同会话消息中读取最近八个完成的真实轮次，最多看八轮。当前问题单独处理，较短会话使用实际轮数。观察文本只用于当前流程的指代、重复和情境判断，正文留在原来的聊天消息中。工具、旁白数据、已撤回内容和其他会话不补入最近轮次。
3. 构造短的本轮指引，次序为当前明示要求、问题类型、接话动作、可用场景和表达限制。聊天可用动作包括直接答、倾听、简短安慰、接玩笑、承认更正和自然结束。指引只给动作选择和节奏，聊天回复仍使用原来的输出契约。关心、任务和情境不确定时按既有范围降级。
4. 用户明示的回应方式和本轮偏好优先于长期习惯。最近开头、别称或口癖重复到阈值，才生成针对性的约束。没有可信关系证据时，使用当前渠道已确认的称呼与普通相处方式。
5. 外部取用优先选择 B 站字幕、转写和评论、贴吧实际帖子中的对话方式。已授权的多个独立真实样本支持同一策略时优先取用。较少样本只能支持与当前话题明确相关的有限接话方式。原句沿用原授权条件，只作口语节奏参考。贴吧登录内容及通用插件沿用宿主既有的原句边界。每轮最多选择一组，保留归属、退订、纠正、停用和撤回。正式写作、急事与倾诉情境沿用适用性筛选。

验收覆盖普通登录私聊、共享渠道、外部私聊、受管任务、明示偏好、矛盾偏好、自然结束、少于八轮、八轮上限和重复检测。用模型请求捕获确认动态提示落在运行时上下文，原消息角色和提供者工具结构一致。自然度用现有盲评入口、合成素材和同一个本地模型比较，分别记录台词具体性、对当前要求的贴合、人物语气、重复、追问和事实。没有可用本地模型时，记录为缺少自然度实测，保留请求验收。

## 3. 记忆抽取、回忆规划与注入

1. 在原有完成轮次、批次队列与来源核验之后抽取。向量条目保留原内容作为细节，增加可选梗概和事件日期。梗概与同一条原文绑定，时间必须能由该条已验证的用户文字支持，不采用模型猜测日期。单条字段错误降级或跳过该条，其他候选仍可保存。老记录可运行时用片段作梗概，缺失事件日期继续表示未知。
2. 共享规划器接受当前查询、用户时区、时间和来自合格本会话的短指代线索。输出最多四个主题、完整短语、候选词、日期范围和时间语义。没有内容的附和不触发。明确指定事件日期时保留经证据支持的事件日期，问某天“聊了什么”则按权威消息时间匹配。时间范围使用左闭右开，覆盖中文绝对日、相对日、周边界和夏令时。明确分成多个日期子句时按各自日期查记忆，同一段有无法拆分的互斥日期时省略自动注入。
3. 向量走现有一次有界语义查找，再对本地候选按多主题词法匹配。摘要和 Wiki 选择同一约束下的可证实片段。仅在相关且证据足时提供有限细节，较弱结果只给有限梗概，低相关、日期缺失或来源无效时省略。已提供给当前窗口的事实统一去重，正文和索引不另存重复副本。当前会话压缩摘要的连续性职责保持独立。
4. 保持每种模式原有写入和管理方式。跨模式读继续走现有权限和证据校验。查询和异步返回时检查版本与撤回，主请求组装和图片转写降级在最后一次视觉等待后再检查模式版本。系统归档、用户遗忘和明确更正保持各自语义。较弱的匹配仅作为查找线索，需要确证时用历史工具复核。

验收覆盖同一事实的向量、摘要和 Wiki 请求，强弱匹配、多意图、事件日期与会话日期、旧数据、已更正的事实和模式关闭中的在途操作。加测两个联系人、工作区、编辑、删除及重启。记录主要匹配成功、错误日期和请求体积。

## 4. 翁法罗斯的提交与可知事实

1. 保留任务租约、日期、时区、取消、版本和请求额度。模型返回后，在一次同步提交中按最新状态重验居民、地点、时间段和前提。事件已被结算、有关设施或事务已改变、计划互相冲突时拒绝。普通起居推进且未改变事实依赖时允许提交。结算目标继续以稳定 ID、版本和状态校验。
2. 每日全局回顾只接受可分享的世界日记。回顾请求前和提交前核验来源。现有旧回顾有可核对的私有日记指纹时，从自动回顾、归档取用和失败回退中排除。此前已经裁剪且缺指纹对应材料的历史无法逐条重新证明，不为它们补造来源。会话专属日记保留于当前会话的可知视图。
3. 新计划记录生成采用的资料版本，新结算记录采用的资料版本和来源。编年史保留计划、发生与结算时间，旧记录未知时按未知读取。仍使用同一存档和归档设施。当前锚点仍是铁墓决战后的记忆延续，运行时状态只说计划、亲历或确已听闻的结果。原作历史、世界规则、续写事件保持来源标签。
4. 重大结算审核按事件记录相关事实 ID，检查该事件的参加者及适用史料。结构化影响和状态前提仍由宿主验证。按既有字段向观察界面呈现可确认的时序与资料版本。

验收用生产存储、延迟模型和假时钟复现半小时跨界，分别验证合法提交及真实冲突拒绝。用合成私有邀请走落盘、预览、实际模型请求和持久回顾。另测旧存档、重启归档、重复结算和隔离 Web 浏览器脚本。

## 5. 历史搜索与读取

1. 与记忆共用纯规划器。中文使用可查短双字词的本地 FTS，英文以整词匹配。按原短语、标题和词项覆盖排序，以时间过滤和稳定打破并列。查询不用外部向量。使用派生索引时必须再到当前权威轨迹验证实际内容、主体、可见性、修订和遗忘状态。索引载入失败时允许有界回退，提示覆盖不完整。
2. 在会话 DB worker 上记录索引状态与可重建正文定位，长期正文由原会话存储。提供版本化 schema 及分批重建。每批至多导入一个规模未知的旧会话。单个超大已导入会话可独占一批，保持完整轨迹回放。正常追加、修改、撤回、删除和重命名使过期候选退出命中，失败可重跑。
3. 搜索返回候选会话、时间、可验证定位和后续游标。相关性分页在本轮保留有限的稳定候选，原文读取用权威消息序号及 ID 向前翻页。游标绑定当前运行、会话、查询和有效期。源修订变化时报告需重新查询。原有 `offset`、`before` 和会话 ID 参数可以继续使用，索引变动时使用不透明游标保持页间稳定。
4. 历史工具取得的正文仅用于该模型请求。成功回复和权威轨迹一同保存安全定位、会话标题与可见正文的指纹，复用既有来源展示和跳转。会话重命名、同一消息编号的正文更新、原始来源失效或无法证明完整来源时，该派生答复退出后续自动历史检索。用户仍可查看原会话并手动选择引用。

验收覆盖两字中文、拉丁词边界、精确标题、多意图、相对日期、无答案、超过原限额的会话、检索失败、跨运行与过期游标、编辑后分页、权限变化、重启以及来源撤回。记录标注集的前五命中、误匹配、重复漏页，合成库记录索引重建和调用延迟。

## 6. 集成复核与放行

| 复核点 | 约定 |
| --- | --- |
| 模型请求 | 普通私聊继续使用现有提供者和回合次数。历史工具负责按需核实，自动记忆只提供少量证据，动态指引决定如何接话 |
| 数据边界 | 世界、事实、表达分别沿用自身权威来源。环境和关系材料继续按当前请求范围注入。模式、通道归属或来源发生变化时立即过滤 |
| 生命周期 | 旧数据继续可读，新索引可重建。更正确认使用新版本，删除由权威读取先阻断，陈旧索引只能降低覆盖 |
| 主入口 | 定向 Vitest、两插件 Node 测试、共享核心认证 Web 及 Electron 请求探针，随后运行四组类型检查、完整 Vitest 和相关构建 |
| 放行 | 零越权，零撤回复活，零重复结算。只有运行得到的结果才能填执行记录，在途或环境受限的检查单列 |

施工前定向基线为 5 个文件、149 项通过。复核了两仓差异和现有角色、记忆、回顾、历史入口，新增的共享边界只有查询规划和带来源定位的回执。仓库现成依赖可直接用 Node 启动 Vitest 和 TypeScript，避免宿主默认 pnpm 审核依赖时触发重装。实现后的命令、结果和有限制的项记录在本文末尾。
