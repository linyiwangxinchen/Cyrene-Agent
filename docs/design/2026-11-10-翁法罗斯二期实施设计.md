# 翁法罗斯二期实施设计

本轮按完整性复审实施，开发前确定如下契约。原有资料索引及复审记录继续保留。

## 数据与迁移

外层个人生活兼容文件仍为 `amphoreus-world.json` version 3，内层世界升级为 schema 2。首次升级保留 schema 1 原件备份；保留已发生事件 ID、日记和自拍关联。旧的未发生事件只保留计划，不把预写结果当成已发生事实。

新增逐人状态：精力、当前位置、当前关注、目标进度、个人经历、已知消息、关系变化、最近实质活动时间。三子拥有三个居民 ID，以同一个 `heirSeat` 关联；旧 `tribios` 参与记录按组转换，并保留原事件 ID。

原子 JSON 快照保存当前活动状态；新增独立 `amphoreus-history.sqlite`，使用项目已有的 Node SQLite 技术记录历史事件、个人经历、事务版本和停机区间。先提交完整快照，再幂等归档，归档成功后压缩快照；归档失败时不裁剪，重启可重放归档。这样归档不会公布尚未提交的结果。已完成历史可以分页读取，未结事务不按阅读窗口裁掉。

## 人物、作息与环境

资料区分官方事实与项目日常方向。统一生成与聊天使用的身份/历史约束，保留原世界书及用户自定义内容，但明确当前资料优先级与历史适用时期。

居民具有不同睡眠、餐食和工作时间；按目标、休息需求和最近经历选择个人活动。普通生活通过确定性调度推进，不逐分钟请求模型。私人的阅读、练习、整理等活动有来源明确的记录，不能伪装成公共项目成功。

地点增加开放/受阻状态、设施状况和粗粒度供给；地理通路与耗时明确标为本项目调度假设。出行需要时间、可通行路线和可用活动窗口。固定身份、火种和历史不属于可变环境字段。

## 规划与结算

模型区分 `plan` 和 `resolve` 两种请求。规划给出目标、参与者、时段、前提、因果引用与可申请的影响，不返回未来结果。结算仅接收已经到期且仍满足状态版本的事件，返回完成/部分完成/失败，以及受限的状态变化。

引擎检查前提、冲突、体力与通行；不满足时给出原因并延期或取消。结算结果在一个快照变更中同时影响居民、环境、事务与个人记忆。事件重复执行无重复影响，版本不匹配的迟到结果不写入。

默认每天最多 8 次模型请求，共享规划/结算预算；单任务最多 3 次，失败退避 30 分钟，90 秒超时。每日最多一个成功日计划，结算可以批量处理多个已结束事件。预算用尽保留待结算事项，次日恢复。普通时间推进不收费调用。

设定一致性采用不可变字段白名单、结构化效果约束和文本冲突检查。重大变化需要更严格的事实引用与审核；这些边界不能被宣称为对任意自然语言的完美验证。

## 连续性与认知

所有主动聊天场景都注入世界认知。完成事件使用结果，未发生计划不得被当成回忆。亲历立即形成记忆；公开消息在发布后、居民合适的日常活动中才被听闻，记录消息来源。角色认知和观察页的全局视图分别构建。

切换时区保留已发生历史，正在进行活动明确中断或过渡，未开始事项重新验证安排，不能覆盖新时区的睡眠/餐食。过期生成租约先收敛为中断状态，再判断剩余预算。

停机多日保存显式区间，按有界时间步结算已知生活规律，并在恢复后的规划中提供缺口与未结事项。不伪造停机期间的模型调用或未验证的公共结果。

## 页面与接口

保留一级入口和按需加载，增加城邦概览、个人经历/目标/关系详情、事件前提与后续、分页编年史、离开后变化和生成物预览。敏感文件路径不进入视图；图片按 ID 按需读取并校验格式和大小。隐藏页面停轮询，地图使用轻量 SVG，历史分页限制单次响应体积。

## 验收

1. 将复审 F1–F8 转为行为回归测试。
2. 一周场景验证个人经历影响次日选择、事件前提失败阻止后续、环境变化影响出行、听闻与亲历分离。
3. 90 天压缩演练验证未结事务保留、历史分页、重复结算、重启恢复和居民覆盖。
4. 聚焦测试、四端类型检查、生产构建与 Web 预算、隔离共享核心及桌面/手机浏览器验证。
5. 有可用的隔离连接和模型配置时补 Linux/真实模型验证；分别记录构造数据与真实运行证据。
