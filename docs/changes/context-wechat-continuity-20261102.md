# 压缩后任务续接与微信会话修复（2026-11-02）

## 问题与证据

用户反馈 Linux Web 长会话在压缩后无法继续原任务，微信出现不回复或答非所问。当前生产服务不可访问，本次使用真实 SQLite、编译后的 Web 共享核心，以及模拟上游响应的 iLink 适配器复现。以下是代码与回归测试确认的缺陷，不能据此认定远端每一次异常都出于同一个原因。

1. **执行状态被归档隐藏**：原检查点保存文本摘要和图片引用，但未保存任务清单、结果尚未确认的工具操作。旧条目离开热记录后，恢复器找不到原 assistant，导致任务状态消失。重启不能自动修复。
2. **微信去重只读热记录**：压缩归档后的用户消息、助手回复和投递回执无法查到。微信重投旧消息时可能重新调用模型；追加用户条目的幂等逻辑又会返回旧行，使本次运行错误地使用较新的上下文。
3. **迟到的工具状态被忽略**：工具在摘要提交或归档前后才完成时，已完成的待办可能仍被恢复为未完成。新增四个时序测试复现并覆盖了这个边界。
4. **取消无法打断压缩准备阶段**：Web 运行准备阶段已经创建会话取消控制器，但尚未注册到 activeRuns。此时点击取消无法中断摘要；忽略 signal 的摘要实现还可能长期占住会话。
5. **排队后重新解析微信绑定**：长时间压缩期间更改绑定，已经到达的消息可能被转移到另一个会话。绑定聊天的模型选择也未用于渠道回复、图片理解和摘要的统一配置。

## 实现变更

| 模块 | 具体修改与目的 |
| --- | --- |
| `conversation-transcript-types/validation` | 为检查点增加可选执行恢复状态与快照序号，验证数据结构；兼容没有这些字段的旧检查点。 |
| `conversation-transcript-compactor/projection` | 在归档前保存任务清单和未确认操作，重建上下文时恢复；显式清空的待办保持为空，已确认结果消除旧阻塞，已消费的一次性重试授权不会再次恢复。 |
| `compaction-recovery`、journal/context 入口 | 旧检查点首次读取时从完整审计记录恢复截至检查点的执行状态，按检查点缓存小型状态。不会把原始长历史重新拼进模型请求，也不要求清空会话。 |
| `conversation-database/worker` | 检查点提交与归档均检查恢复状态的并发变更；归档后的迟到工具结果重新开放必要的记录投影，文本上下文仍遵守摘要边界。 |
| `getChannelTurnState` 与专用数据库查询 | 按指定渠道轮次查询用户条目、助手条目和投递回执，包含归档范围；增加轮次索引，避免每条消息读取整段历史进行去重。 |
| `dispatcher/channel-context` | 到达时锁定绑定目标；处理前确认目标仍存在；抑制旧消息重投、重复 UI 气泡和重复回复。已经被后续问题替代的旧失败消息不再次触发模型。 |
| `channels/bootstrap` | 绑定微信继承目标会话模型档案；图片路由、摘要和回复使用相同设置；去掉强制默认 style，遵循当前配置。绑定不扩大工作区权限。 |
| `agui-bridge` 与压缩生命周期 | 取消覆盖运行准备阶段；压缩总预算为五分钟，同会话并发压缩合并；忽略取消的摘要也可及时释放，迟到结果不能写入检查点。 |
| `build-options` | 自动压缩后重读日志，确认最新用户问题仍是本次请求，避免 Web 与微信并发输入时把别人的问题、附件和收件人混用。 |
| 摘要与记忆提示 | 历史放在待整理数据中，明确当前目标、已完成/取消状态、最新纠正与未验证推测；历史记忆不代替本轮问题。摘要目标调整为 400–1200 字。 |
| 自动压缩切点 | 旧首轮极长而近期尾部很短时，缩减保留预算到安全切点，避免有可压缩历史却持续报无安全切点。 |
| Linux CI | 加入微信压缩重启集成与 journal 恢复测试，继续通过共享核心服务覆盖 Web 和 Windows 业务实现。 |

本次不修改已有模型账号、微信凭据、用户记忆内容或权限档位，不删除原始会话审计记录。

## 验证

专项测试覆盖压缩取消与超时、任务清单/未确认操作归档后恢复、旧检查点恢复、二次压缩、迟到工具结果、微信重投去重、连续新消息、绑定变更、会话模型继承及 Web/微信并发问题保护。

- 全量 Vitest：634 个文件通过，6692 项通过、5 项跳过；使用默认 forks 池。
- Main、Preload、Server、Renderer 四项类型检查通过。
- `pnpm run build:web` 与 `pnpm run build` 通过；使用仓库声明的 pnpm 10.33.0。
- `node scripts/verify/shared-core-compaction.mjs`：10 项通过，包括真实认证 Web 入口中的压缩前取消、HTTP 摘要中断、自动压缩后继续回复和重启恢复。
- `node scripts/verify/shared-core-memory.mjs`：4 项通过，包括后台记忆请求失败后服务继续可用、SQLite 锁重试、重启补做及避免重复提取。
- `node scripts/verify/shared-core-parity.mjs`：34 项通过，包括 Work/Code/Learn、工具、插件、知识库、调度、渠道附件和持久化。
- 新增 iLink 集成测试使用真实适配器、队列和 SQLite，模拟网络响应；覆盖压缩重启后旧失败消息与已回复消息重投、两条新消息连续回复，以及各自的微信 context token。
- 构建产生的 `dist/renderer` 换行差异已核验并恢复；不提交构建产物。

运行端是本地 Windows；隔离 Web 服务执行正式编译的无桌面共享核心。Linux CI 已补充对应回归用例，本次没有将本地通过的结果等同于远端 Linux 实机或真实模型回答验收。没有重新发布安装包。

## 部署与复核

按 Linux 构建指南中的现有更新代码拉取、安装依赖、重新构建 Web 并重启服务。只拉取源码而未重新构建和重启，不会让正在运行的服务加载修复。无需删除数据库或新建会话；旧检查点会按需恢复执行状态。

更新后在原微信绑定会话中继续原任务，再发一个与原任务相关的新问题，检查模型是否使用最新消息并延续任务约束。检查 Web 与微信是否一致，确认同一条旧消息没有重复回复。如果仍有答非所问，需要提供该轮脱敏前后文、服务版本和对应时间段日志；本次未读取当前远端会话，也未调用真实模型或向真实微信账号发送消息。
