# 小花园在其他视频中收到 @ 后不回复（2026-11-02）

插件版本更新为 `0.1.1`。用户确认：在其他 UP 视频的一级评论中 @ 昔涟，评论守护、自动发送和发起者 UID 白名单均已开启。当前远端不可访问，本次以本地源码、已安装的 bilibili-api-python 17.4.2 和隔离测试定位缺陷。

## 已复现的原因

1. **通知翻页方向错误。** SDK 的 `get_at(last_id, at_time)` 参数用于继续读取较旧的通知。旧实现把上一轮的返回游标直接传到下一轮，并把它当成新消息水位，第一次扫描之后就可能持续查询旧页，漏掉新来的 @。
2. **两个扫描入口互相阻塞。** 在读取 @ 前先请求目标 UP 视频列表；该接口失败会让整个守护扫描退出，即使 @ 所在的其他视频与目标 UP 无关。
3. **仅接受 URI 中的 BV 号。** 通知只给 AV 链接、原生客户端链接或视频 aid 时，无法生成 bvid，随后被静默过滤。
4. **无字幕造成整个回复被禁止。** 所有公开互动都要求视频字幕/转写证据。即使白名单用户只是呼唤昔涟，模型也不能回复“我在”或说明读取限制；空报告可能把未回应标成任务成功。
5. **用户无法看到阻断位置。** 原界面没有最近扫描的通知数量、白名单过滤数量和部分接口失败状态，难以区分没收到通知、没处理和没发送。

这些是代码中可以复现的缺陷，不代表已经核对当前服务器上具体哪一个条件触发。

## 修改范围

| 文件/模块 | 修改用途 |
| --- | --- |
| `python/mention_scan.py` | 单独实现 @ 轮询：新通知从首页开始，最新已扫描水位与历史翻页进度分开保存；每轮页数有界，未扫完的历史下轮继续。兼容同秒通知、网络失败、AV/aid 链接和楼层根 ID，拒绝把动态或文章通知当作视频评论发送。 |
| `python/bilibili_backend.py` | 守护扫描调用新的通知处理器，返回通知水位、续扫进度和计数；与原视频评论扫描共用现有凭据和进程，不增加依赖。 |
| `lib/service.mjs` | 视频列表失败仍扫描 @；队列和游标在一个 SQLite 事务内落盘；暴露扫描状态；避免扫描与模型任务交错启动；支持用户手动重新入队明确未完成的 @。 |
| `lib/policy.mjs` | 仅对已在守护队列中的 @ 原评论允许基于评论文字回应。普通视频评论、赞藏等仍要求视频内容证据；发送前仍检查账号、白名单、开关、额度和结果幂等性。 |
| `lib/runner.mjs`、`charter.md` | 明确守护回复独立于闲逛评论模式。无字幕时尝试回应原评论或说明限制，禁止编造视频内容；未处理 @ 不能用空报告伪装成功；未发送草稿记录阻断原因。 |
| `lib/store.mjs` | 查询达到重试上限的未完成 @，排除已发送、发送中、结果不明、待审核草稿及用户已放弃的记录。 |
| `panel.js` | “互动”页显示扫描状态、过滤数量、分页积压与失败原因；提供“扫描 @ 与评论”“重试未回复的 @”，兼容桌面和手机宽度。 |
| `manifest.json`、`README.md` | 标记插件版本，补充其他 UP 视频下的提及用法和更新后的恢复方法。 |
| 验证脚本与 Linux CI | 增加通知分页、原评论回复、重复抑制、恢复和界面状态回归；在无桌面共享宿主中验证真实工具调用流程。 |

没有修改全局模型、微信、长期记忆或权限实现。新 Python 模块属于昔涟插件本身，不引入 DSH 运行时。

## 更新后使用

按原 Linux 更新脚本拉取、重新构建并重启服务，然后刷新浏览器。若 Git 提示源码被修改，先保存本地修改再更新。插件应显示 `0.1.1`；本次不需要重装 Python 依赖或 Whisper 模型，也无需删除账号或数据库。

进入“小花园 → 互动”，点击“扫描 @ 与评论”，查看最新扫描结果。若旧 @ 已连续失败达到重试上限，点击“重试未回复的 @”，再扫描；该操作只恢复仍在白名单内、没有已发送或不明发送结果的记录。此后正常后台扫描仍遵守静默时段、扫描间隔和每日额度。
