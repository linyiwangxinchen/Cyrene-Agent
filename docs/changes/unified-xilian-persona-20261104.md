# 统一昔涟人格改造

## 核心修正

方案中的“虚拟女友”和“虚拟助手”统一为同一个主体：昔涟。Chat、Work、Code、Learn、Web、Windows 和外部渠道只代表能力职责、工具范围和表达密度，不代表换人或切换人格。

## 本次实现

- 新增 `src/main/persona/persona-spec.ts`：集中定义昔涟的 `PersonaSpec`、关系状态、情绪状态、权限档案和默认状态构造器。
- 所有模式共享 `soul.md`，并追加统一人格契约；模式提示词不能再只通过“保持 soul”间接引用人格。
- 统一契约明确：亲密度不能扩大文件、频道、浏览器、MCP 或外部消息权限；工具授权由独立策略决定。
- 修正 Code 模式错误引用 Learn 模式的问题，去掉 Learn 模式的重复声明，补全计划协作身份。
- Web 与 Electron 共用同一 `MODE_PROMPT_FILES` 和模式组合函数，因此 Linux/Web、Windows、微信、飞书、QQ 的提示词身份保持一致。
- Web 新增只读 `GET /api/persona` 和偏好更新 `PATCH /api/persona/relationship`；接口只允许修改称呼、共同目标、重要时刻和边界，不允许直接写入亲密度、情绪数值或工具权限。

## 验收边界

本次完成的是统一人格基础层和领域模型骨架；关系状态的长期持久化迁移、情绪衰减引擎、权限中心 UI、记忆治理 UI 和多端管理 API 仍应在后续阶段接入这些类型，不能把当前的关系日志误称为完整关系状态机。
