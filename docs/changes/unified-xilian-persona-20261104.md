# 同一个昔涟：改造说明与使用方法

## 设计原则

“虚拟女友”和“虚拟助手”都是昔涟。Chat、Work、Code、Learn 表示任务方式，Windows、Web、微信、飞书和 QQ 表示入口；它们不能改变正在与用户交流的人物。原有 soul、角色资产、工具执行、渠道、长期记忆和任务编排继续保留。

相处方式与执行权限分别控制。更亲密不能获得更多文件权限；办事能力也不能以用户表达亲密为前提。开发路线及原方案的取舍见 [设计修订](../design/2026-11-04-unified-xilian.md)。

## 从哪里使用

更新后，Windows 重新构建主进程、preload 和 renderer，Web 重新运行 `pnpm run build:web` 并重启服务。只刷新旧服务页面不能加载新后端。

进入 **设置 → 昔涟设置 → 同一个昔涟**：

1. **相处与形象**：设置称呼、语气、亲昵表达、相处程度、共同目标、重要时刻和边界；点击“保存相处偏好”。跨四种任务模式生效，不会新建另一位角色。
2. **能力与权限**：选择额外能力限制，配置禁止调用或每次确认的工具；点击“保存能力限制”。默认沿用现有授权，不静默扩大权限。
3. **记录与修复**：查看带时间和来源的互动线索、记录新的相处约定、删除误判、导出或清空关系数据。

相处程度由用户明确选择，范围 0–100。不因刷消息自动升级，也不因为几天不登录扣分。初识、熟悉、亲密和长期陪伴是表达偏好，不是真人关系的判定。

“暂停关系模拟及主动关怀”停止新关系线索和主动消息，不影响完成用户主动发起的任务。“记录本轮关系线索”只控制关系日志；原始聊天和长期记忆有各自的开关。

“暂停新工具调用”阻止下一次工具执行，包括渠道自动批准和插件后台目标任务。已经执行的外发、写入及正在运行的进程不会被撤销；停止当前任务仍使用原有停止入口。

## 人格、状态与多端一致性

- `persona-spec.ts` 定义唯一身份、表达与权限边界；四个任务模式直接加载同一份 soul，再补充各自职责。修正旧 Code 模式误提 Learn 及部分模式未直接加载完整 soul 的问题。
- 通话、主动消息、定时任务及普通会话使用同一人格契约。设置经共享主进程核心注入，正式 Web 使用认证后的 core transport，不依赖旧的实验 HTTP persona 路由。
- `xilian-pack.ts` 集中保存角色包版本、资源引用、语言规则与虚构小记。未替换 Live2D、贴图或许可证；Linux Web 不需要桌面环境。
- 情绪是派生表达线索，会随时间回归基线；读取状态也计算衰减。`runtimeSync=local` 下映射到已有表情；`llm` 与 `off` 保持原有含义。
- 自动情绪判断是关键词启发式，界面标为自动线索，可以删除。它不能作为用户心理状态的事实，也不提高关系程度或授权。
- 互动上下文按会话隔离；群聊和插件公开任务不注入个人关系上下文。绑定同一会话的微信延续该会话线索。用户明确填写的全局个人偏好只供个人入口使用。

## 主动关怀与生活细节

“虚构角色小记”默认关闭。启用后，每天首次构建个人上下文时至多生成一条明确标记虚构的短叙事；不额外调用模型、不独立通知，不声称现实中发生过。删除当天小记后不会立即重新生成。

“共同目标与重要时刻主动关怀”默认关闭，且要求原有主动聊天总开关开启：

- 重要时刻写 `MM-DD 名称` 表示每年，或 `YYYY-MM-DD 名称` 表示单次，例如 `11-04 项目纪念日`。
- 日期命中形成候选；共同目标在适当白天形成低频候选。只有最近七天内有有效会话活动才参与判断。
- 继续经过原有目标评分、冷却、勿扰、连续未回复退避、渠道可用性与发送前检查。不达标时不会硬发。
- 偏好设置显示最近选中候选的原因。生成期间用户修改关系或授权设置，旧设置下的待发消息不能提交。
- 不保证定点触发。精确时间、重复提醒和工具任务仍使用原有定时任务。

## 能力限制的执行含义

| 设置 | 实际效果 |
| --- | --- |
| 沿用现有授权 | 不增加限制；原权限、目录策略继续生效 |
| 仅无副作用的基础工具 | 只允许明确标为读取且风险为 safe 的工具 |
| 基础查询 | 只允许读取，风险限 safe、文件读取或网络查询 |
| 日常协作 | 读取和文件写入按原权限；其他操作需要确认 |
| 完整能力 | 读取按原权限；写入、外发及未知副作用需确认 |
| 禁止调用 / 暂停 | 即使渠道配置自动批准，也拒绝执行 |
| 每次确认 | 无审批界面的后台任务拒绝，不绕过确认 |

限制在执行入口判断，审批等待后再次检查撤回。子任务沿用父任务权限回调；插件后台目标任务也经过附加限制。相处程度不参与算法。

这是附加限制，不赋予系统权限。目录、渠道、原文件权限、Plan 只读、工具副作用检查和执行账本仍有效。同进程插件仍是可信代码，直接调用操作系统 API 的行为不属于工具网关，不能称为操作系统沙箱。

## 记忆治理

进入 **设置 → 记忆 → 向量模式**，每条 L2 记忆新增“来源与管理”：

- 查看来源会话、原始引用和证据；历史记录未保存置信度时显示未知，不制造评分。
- 修正正文后重建检索索引。旧向量及包含旧内容的派生摘要失效；索引未完成前不召回旧版本。
- 归档后停止召回；删除同时删除沿 `subEntryIds` 引用的派生摘要、证据与向量。
- 外部索引清理/重建失败时显示警告，正文状态先落盘，旧内容不能通过本地有效性检查。
- 导出 L0/L1/L2 数据；L0/L1 编辑、Wiki 和摘要管理沿用原入口。

关系中心管理独立派生记录，不等于删除整个长期记忆。删除关系记录会清除相应线索、派生日摘要并重置模拟情绪；删除会话也清理对应关系记录。重置关系不重置或提升工具权限。

删除 L2 不自动删除 L0/L1 中已提炼的事实、原始聊天、Wiki、Obsidian 文件及手动备份。未删除的原始来源仍可能被既有记忆处理重新分析；本次不承诺跨所有存储介质的“永久遗忘”。

## 持久化与迁移

- 新状态保存在数据目录的 `relationship-log.sqlite`，使用 SQLite 事务、模式版本与独立设置 revision。
- 首次使用导入旧 `relationship-log.json` 并保留原文件；格式或数值损坏时报错，不用空数据覆盖。删除关系数据时同时清理旧 JSON，防止重新导入。
- 普通互动不增加设置 revision；多窗口同时修改设置时，旧窗口需重新加载。
- 保存 CTA 会话/run/事件引用及派生线索；兼容旧日志，仍保留每轮最多各 500 字的用户/回复片段，不建立第二份完整会话权威。
- 来源事件幂等去重，删除后重放同一事件不会立即恢复记录；保留最近一万条去重引用、500 条关系日志和 90 条日摘要。
- 新数据库和导出不包含 API Key；不改变其他模块既有密钥格式。

## 代码分区与同步

新逻辑集中在 `main/persona`、`main/relationship`、`main/character-packs`、独立记忆治理模块和新增设置面板。既有编排、渠道、主进程与 headless 核心只增加入口，共用 `shared/companion.ts` 和 `shared/memory-governance.ts`。

保持上游文件结构，不另建 Web 人格实现。未来合并仍需关注 `build-options.ts`、`agent-runtime.ts`、`permission.ts`、IPC 注册与 preload；不能保证共同修改文件永远自动合并。

## 可复现验证

使用 package.json 固定的 pnpm 版本和 Node 24，在项目根目录执行：

```bash
pnpm run check:main
pnpm run check:preload
pnpm run check:renderer
pnpm run build:main
pnpm run build:preload
pnpm run build:web
pnpm exec vitest run --maxWorkers=4
node scripts/verify/companion-flow.mjs
node scripts/verify/companion-flow.mjs --ui
node scripts/verify/shared-core-parity.mjs
```

`--ui` 使用已安装的 Playwright Chromium；Windows 可设置 `CYRENE_TEST_BROWSER_CHANNEL=msedge` 使用本机 Edge。脚本采用临时数据、随机本机端口与测试账号，不连接真实微信或消费模型 Key；结束后关闭测试服务并输出证据目录。

状态模拟、提示词契约和本地假模型验收不等同于真实模型百轮人格评测。真实渠道投递、模型长期相处、语音硬件、TTS 表现与原生 Linux 运行需要相应环境另行验收。
