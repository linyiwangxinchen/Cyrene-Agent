# Web 主动消息检查（2026-10-09）

## 结果与修复

Web 偏好设置将 `proactiveChatMode`、`proactiveDeliveryTarget` 保存到共享通用设置。保存时使正在生成的主动消息失效，无需重启。Headless runtime 初始化主动聊天服务并启动触发器，普通聊天与渠道聊天接入用户活动和会话生命周期。

发现并修复：主动候选使用用户时区，生命周期硬策略却使用服务器系统小时。UTC Linux 服务器会错误地执行深夜禁扰。`proactive-lifecycle.ts` 改为使用用户有效时区，与候选时钟一致；Windows 同样受益。

## 现有行为

- 需在偏好设置点击保存；开启不会立即发送。启动后首轮扫描延迟 90 秒，后续约 60–70 秒扫描一次，并按场景评分挑选候选。
- 普通聊天期间不打扰；聊天结束后静默 30 分钟；主动发送之间至少 2 小时。同场景还有独立冷却。
- 连续一次未回复，后续追问至少间隔 6 小时且必须换场景并达到更高分；连续两次未回复暂停。用户发消息会重置未回复计数。
- 用户时区 22:00–08:00 且空闲至少 60 秒时不发送。Web 空闲由浏览器键盘/点击活动以及聊天请求更新，不监测远程用户电脑的其他应用。
- 目标为本地：写入独立的“昔涟的主动消息”会话并广播会话更新，不自动插入当前普通聊天。浏览器关闭时仍可落库，下次打开读取。
- 微信/飞书：渠道须处于运行状态，且本次服务运行期间收到过对应渠道消息以确定收件人。收件人登记当前仅在内存中，重启后需再发送一条消息。QQ 不属于此设置的主动投递目标。
- 使用默认模型档案。模型可以明确选择静默；模型失败不使用固定话术兜底。渠道不可用时当前实现取消本轮，不切换为本地投递。

## 验证范围

10 个相关测试文件、85 项测试通过，涵盖策略、触发器、模型协议、渠道投递、设置保存及生命周期。新增生命周期测试验证 UTC 服务器/上海用户的白天投递、深夜拦截、关闭开关拦截，以及 assistant 写入、presentation 写入、会话刷新通知和未回复计数更新。Server 与 Windows main 类型检查通过。

本次未修改远程生产设置、未向用户微信/飞书发送测试消息，未对远程当前版本和生产模型进行现场投递验收。生产日志可通过 `sudo journalctl -u cyrene-web --since today --no-pager | grep -E '\[Proactive(Trigger)?\]'` 查看候选选择、策略拦截、模型静默及投递结果。
